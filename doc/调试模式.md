# 调试模式

light-ide 不在页面里打断点。调试模式只让项目以 JDWP 启动，断点打在 Cursor 已经打开的源码上，再从 Cursor 附加到这个进程。

已经在跑、并且启动时没有勾选调试的进程，不能事后补上调试。先停止，勾选调试模式，再启动。

Cursor 需要安装 Extension Pack for Java。用 Cursor 打开的目录必须包含正在跑的那份源码，断点才能对上。

## 启动

1. 选中运行配置，勾选「调试模式」。端口默认 `5005`。保存。
2. 点启动。进程起来后，工具栏出现「复制 Cursor 附加配置」。
3. 在项目里准备 `.vscode/launch.json`。没有这个文件就新建。把复制的内容放进 `configurations`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "java",
      "request": "attach",
      "hostName": "127.0.0.1",
      "port": 5005
    }
  ]
}
```

4. 在源码里打断点。打开「运行和调试」，选中这个 Attach 配置，按 F5。

改完代码后，在 light-ide 里点重启，再到 Cursor 里重新附加一次。

## Maven / Spring Boot

goals 必须包含 `spring-boot:run`。调试参数写在业务进程上：

```text
-Dspring-boot.run.jvmArguments=-Xmx1024m -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005
```

`suspend=n`，应用会先正常启动，不等待调试器。F5 附加之后，请求进到断点才会停住。

不要在「额外参数」里再写 `spring-boot.run.jvmArguments`。调试模式自己会设置这一项，两边同时写会导致启动失败。需要改堆大小时，关掉调试模式，只在额外参数里保留一项，例如：

```text
-Dspring-boot.run.jvmArguments=-Xmx2048m
```

这样启动时不会打开调试端口。

## Gradle

任务必须包含 `bootRun`。调试模式追加 `--debug-jvm`，端口固定是 `5005`，配置里的其它端口会被忽略。

这种启动会先暂停，进程停在启动处，直到 Cursor 附加后才继续跑。日志里如果一直没有应用自己的输出，先去 Cursor 按 F5。

## 外部 Tomcat

设置里要先填好 `CATALINA_HOME`。调试模式执行的是 `catalina.bat jpda run`，并设置：

```text
JPDA_TRANSPORT=dt_socket
JPDA_ADDRESS=5005
JPDA_SUSPEND=n
```

应用会先启动。端口可以改，Cursor 里的 `port` 要和页面上的端口一致。

## 自定义脚本

脚本配置不能勾选调试模式。脚本里如果还有多层 Java 进程，启动器无法判断该把调试参数加到哪一个。要调试时，在脚本自己的 `java` 命令上加上：

```text
-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005
```

然后用上面的 `launch.json` 附加到 `5005`。
