# 多模块项目启动

light-ide 把一个目录当成一个项目。多模块 Maven 工程的根 `pom.xml` 通常是 `packaging` 为 `pom` 的聚合工程，`spring-boot-maven-plugin` 只写在真正要跑的子模块里。

添加根目录后，如果根 `pom.xml` 里出现 `spring-boot` 字样，页面会给出一条 goals 为 `spring-boot:run`、工作目录为空的配置。不要直接用它。工作目录是根目录时，Maven 按根工程解析插件前缀，根上没有这个插件，会报：

```text
No plugin found for prefix 'spring-boot'
```

反应堆里的模块全部 SKIPPED。`goals` 里加上 `-pl 子模块 -am` 也一样，前缀仍然按根工程解析。

`bin` 里用来 `mvn package` 的脚本只打包，不能当作启动配置。

## 配置

项目路径填仓库根目录。一个可运行的子模块对应一条配置，外加一条安装配置。

**安装依赖**

- 类型：`maven`
- goals：`install -Dmaven.test.skip=true`
- 工作目录留空
- 不勾选调试

子模块之间的依赖要先装进本地仓库。公共模块改过之后再跑一次。只改某个可运行模块自己的代码时，不用重装。

**每个可运行模块**

- 类型：`maven`
- goals：`spring-boot:run`
- 工作目录：该子模块的目录，目录里的 `pom.xml` 要声明 `spring-boot-maven-plugin`
- goals 里不要写 `-pl`、`-am`

同一项目下的多条配置可以同时启动。端口、profile 以该模块自己的 `application.yml` 为准。

前端或其他不是 Maven 的部分用脚本配置，指向它原来的启动脚本。脚本配置不能勾选调试。

## 例子

`D:\workspace\didi-platform` 的根工程是聚合 pom。能跑的是 `ruoyi-admin`（18080）和 `didi-api`（18081），本地 profile 都是 `test`。前端在 `ruoyi-ui`，开发端口 81。

| 名称 | 类型 | goals | 工作目录 |
| --- | --- | --- | --- |
| 安装 | maven | `install -Dmaven.test.skip=true` | 空 |
| 管理端 | maven | `spring-boot:run` | `D:\workspace\didi-platform\ruoyi-admin` |
| 接口 | maven | `spring-boot:run` | `D:\workspace\didi-platform\didi-api` |
| 前端 | script | | 脚本填 `D:\workspace\didi-platform\ruoyi-ui\bin\run-web.bat` |

数据库和 Redis 等环境变量由该项目自己的配置要求，不在 light-ide 里填写。

命令行等价于在仓库根目录执行：

```text
mvn -B install -Dmaven.test.skip=true
mvn -B -f ruoyi-admin/pom.xml spring-boot:run
mvn -B -f didi-api/pom.xml spring-boot:run
```

## 调试

勾选调试的那条配置，goals 必须包含 `spring-boot:run`，工作目录仍然是子模块。用法见 [调试模式.md](调试模式.md)。两个模块同时调试时，把其中一个端口改成 `5006`，Cursor 里的 `port` 也改成同一个。
